# Web 控制台改版：从「看任务」到「推进 Issue」

> 状态：待评审。分 4 个阶段，每个阶段一个 workling Issue，按顺序合入。

## 1. 背景

001-web-spa 把控制台迁成了 React，视觉沿用旧页面。之后闭环调度（002）和 Issue 持续推进（003）加了反馈、PR 返工、返工上限、分诊（影子 / 建议 / 自动）、`workling:needs-info`、持续分支等能力，它们的界面都是往旧页面上贴的：

- 分诊结果只是仓库详情页里两行纯文本统计，没有跨仓库的入口。
- Issue 详情里「反馈」和「执行历史」是两张互不关联的列表，看不出哪条反馈由哪一轮处理。
- Issue 详情仍提示「重新打 `workling:ready` 重试」，没有提 `/workling` 和 `@workling-agent`。
- 概览只列失败任务。PR 待审、返工到上限、信息不全、worker 暂停拉起这些要人处理的事在首页看不到。
- 任务列表只按 `issues.status`（排队 / 执行中 / 失败 / 完成 / 已取消）筛选，没有「PR 待审」「返工中」「返工到上限」。

## 2. 目标

1. 首页回答「现在要我做什么」：把要人处理的事合成一个待处理列表，系统告警置顶。
2. 以 Issue 为主体：Issue 详情用一条时间线串起分诊、各轮运行和反馈。
3. 闭环能力有自己的入口：分诊升为一级导航，跨仓库查看。
4. 状态按**阶段**展示，颜色固定，深浅两套主题都满足对比度。

## 5. 阶段（stage）

阶段由服务端根据现有数据算出，**不新增表字段**。规则与实现见 [stage-1-issue-stages.md](stage-1-issue-stages.md) 第 2 节。

| stage      | 中文       | 颜色 token   | 含义                                      |
| ---------- | ---------- | ------------ | ----------------------------------------- |
| `queued`   | 排队       | `--queued`   | 已入队，等名额                            |
| `running`  | 执行中     | `--running`  | 实现轮正在执行                            |
| `rework`   | 返工中     | `--rework`   | 返工轮正在执行                            |
| `review`   | PR 待审    | `--review`   | 执行结束，PR 打开，等人 review            |
| `capped`   | 返工到上限 | `--rework`   | PR 打开，最近一轮之后有因上限未处理的反馈 |
| `failed`   | 失败       | `--failed`   | 最近一轮失败                              |
| `done`     | 完成       | `--done`     | 执行结束，没有 PR 或 PR 已合并 / 关闭     |
| `canceled` | 已取消     | `--canceled` | 被取消                                    |

「信息不全」不是 Issue 的阶段（这类 Issue 还没进 `issues` 表），只出现在分诊页和概览的待处理列表，颜色用现有的 `--warn`。

## 6. 视觉规则

- 沿用现有布局、字体、圆角和深 / 浅色主题机制（`style.css` 中的 `:root`、`@media (prefers-color-scheme: dark)`、`[data-theme='dark']` 三处 token 定义）。
- 新增两组颜色 token，三处定义都要加：

  | token           | 浅色      | 深色      |
  | --------------- | --------- | --------- |
  | `--review`      | `#0d6e67` | `#55cbc4` |
  | `--review-soft` | `#e3f3f1` | `#10292a` |
  | `--rework`      | `#6844c0` | `#bba2ff` |
  | `--rework-soft` | `#efeafb` | `#251d3d` |

- 新增徽章类 `.badge--review`、`.badge--rework`、`.badge--capped`（同 `--rework`）与对应 `.dot--*`，写法与现有 `.badge--running` 一致。
- 文字与背景对比度 ≥ 4.5:1（含 12px 的灰色说明文字）。
- 宽表格放进 `.table-wrap` 横向滚动；375px 宽时页面本身不出现横向滚动，双栏布局改为单栏。
- 不使用内联 `<style>`（CSP 限制）；React 的 `style` 属性可以用。

每个阶段一个 Issue。四个阶段都改 `src/web/`，**前一个合入后再就绪下一个**。

## 8. 每个阶段共同的验收

- `bun run check` 通过。
- 新增的纯函数有表驱动测试；新增或变更的 JSON 接口在 `test/web.test.ts`（或同目录新文件）里校验形状与状态码。
- 新接口的响应用 typebox schema 校验（与现有 `overviewSchema` 等写法一致），客户端读取时同样 `Value.Check`。
- 深色、浅色、跟随系统三种主题下页面都可读。
- 375px 宽度下无页面级横向滚动。
- 站内跳转、刷新、深链接、浏览器前进后退正常；会话过期跳 `/login`；控制台无 CSP 报错。

## 9. 不做

- 仓库详情拆标签页、设置页重新分组。
- 记录标签变化历史（谁在何时打了 ready）——现在没有这份数据。
- 运行进度百分比、提交数统计——现在没有可靠来源。
- 执行日志页改版。
