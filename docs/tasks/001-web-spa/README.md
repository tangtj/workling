# Web 界面渐进迁移到 React 单页应用

> 状态：草案（2026-11-15），待评审。

## 1. 背景与目标

现在的 Web 界面是服务端渲染的多页应用：Hono JSX 渲染整页，`src/web/assets/*.js` 是原生脚本，Bun 用 text loader 把资源打进后端。每次点击和每次保存都会整页重载，再加上静态资源是 `Cache-Control: no-store`，切换页面时会明显闪一下。

目标：**前后端仍不分离**（同一个 Bun 进程、同一个端口、资源随后端发布），前端分多次迭代逐步换成 React 单页应用。每个阶段单独可上线，任何时候界面都能完整使用。

## 2. 不变的约束

- 不引入独立的前端工程或部署：`bun src/cli.ts serve` 直接可用，Docker 镜像仍然直接从源码运行，不新增需要提交的构建产物。
- 安全边界不变：Host 校验、JSON 请求类型校验、会话鉴权中间件对页面和接口一视同仁；CSP 只放行 `src/web/views/theme.ts` 中固定的首屏主题脚本（按内容哈希），继续禁止其他内联脚本和内联 `<style>`（React 通过 DOM 属性设置的 `style` 不受影响）。
- 接口沿用 `/api/*` 和 JSON；新接口的出入参照样用 typebox 做形状校验。
- 视觉以现有页面为准。迁移阶段只换实现、不改设计，避免一次改两件事。

## 3. 技术选型

| 项         | 选择                                                  | 理由                                                                                       |
| ---------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| UI         | React 19 + react-dom                                  | 目标技术栈                                                                                 |
| 路由       | React Router 7（library 模式，`createBrowserRouter`） | 只用客户端路由，不用它的框架模式和 SSR                                                     |
| 服务端数据 | TanStack Query 5                                      | 轮询刷新（概览 15 秒）、保存后失效重取、请求去重，替代现在的 `location.reload()`           |
| 打包       | `Bun.build`，服务启动时在内存里打包一次               | 不新增构建步骤和产物；产物文件名带内容哈希，可以长期缓存；`bun --watch` 重启时自动重新打包 |
| 样式       | 沿用 `style.css`，由入口文件 `import`                 | 迁移期间新旧页面共用一份样式                                                               |

依赖放在 `dependencies`（镜像里用 `--production` 安装，运行时要打包）。版本按 `bunfig.toml` 精确锁定。

## 4. 迁移方式：外壳先行，页面逐个替换

阶段 1 起，所有页面路由都返回同一个 SPA 外壳，由 React 负责侧栏、路由和页面切换。还没迁移的页面，React 用"片段模式"向服务端要现有的 SSR 内容（只要 `<main>` 里面那部分 HTML），插进页面再调用原有脚本完成初始化。之后每个阶段把一个页面换成真正的 React 组件加 JSON 接口，最后删除片段模式和 Hono JSX 视图。

这样第一阶段完成后，点击就已经不再整页刷新，后续每一步只影响一个页面。

## 5. 阶段

每个阶段对应一个 workling Issue，前一个合入后再就绪下一个（都会改 `src/web/`，并行会冲突）。

| 阶段 | 内容                                                                                                     | 文档                                           |
| ---- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 0    | 止血：静态资源加哈希并长期缓存、`color-scheme` meta、跨页 View Transition                                | Issue 正文即可                                 |
| 1    | React 底座：内存打包与资源路由、SPA 外壳、React 侧栏与路由、旧页面片段模式、旧脚本改为可重复初始化       | [stage-1-foundation.md](stage-1-foundation.md) |
| 2    | 任务列表 `/issues`、仓库详情 `/repos/:id`：只读页，新增列表 JSON 接口，筛选写入 URL                      | 阶段开始前补文档                               |
| 3    | 概览 `/`：用 TanStack Query 每 15 秒轮询，替代片段整块刷新                                               | 同上                                           |
| 4    | 仓库 `/repos`：增删、启停、换 token、添加抽屉；保存后失效重取，不再跳转带 `?notice=`                     | 同上                                           |
| 5    | 设置 `/settings`：各卡片独立保存与未保存状态                                                             | 同上                                           |
| 6    | Issue 详情 `/issues/:id` 与执行日志 `/runs/:id/log`：时间线改为 React（`timeline.js` 的纯函数保留复用）  | 同上                                           |
| 7    | 收尾：版本面板与登录页改为 React，删除片段模式、`src/web/views/`、`app.js` / `run-log.js` / `version.js` | 同上                                           |

阶段 0 和阶段 1 互不依赖，但阶段 0 改动小、立刻见效，建议先做；阶段 1 会接管其中的资源哈希。

## 6. 每个阶段共同的验收

- `bun run check` 通过。
- 迁移过的页面：站内点击、浏览器前进 / 后退、刷新当前地址、直接打开深链接，结果都和迁移前一致。
- 会话过期时任何请求都跳转 `/login`。
- 浏览器控制台没有 CSP 报错。
- 测试覆盖新增的 JSON 接口；页面行为至少用 `test/web.test.ts` 校验路由返回外壳、片段与状态码。
